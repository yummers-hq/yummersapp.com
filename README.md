# yummersapp.com

The public website for **Yummers**, a restaurant discovery app for Cambodia that is still in the making.

The app was called HungryRaccoon until October 2026 (D85). The old domain, hungryraccoonapp.com, forwards here with a Cloudflare redirect rule that keeps the path and query, so share links already sent (`/l/...`) still open (#35). The repo is `yummers-hq/yummersapp.com` (renamed from `hungryraccoon-hq/hungryraccoonapp.com`; GitHub forwards the old address).

This is a plain static page: HTML, CSS, fonts and images, with no build step. It is served by GitHub Pages on `yummersapp.com`. The only server code is the Cloudflare Worker below, which also takes the homepage's Android waitlist sign-ups (#32). It has no download links. Visits are counted by PostHog (`analytics.js`, #2): cookieless until a visitor presses Accept on the cookie banner, and Cloudflare Web Analytics (the zone's automatic setup, no cookies) still runs until the owner switches it off (#51).

The app itself lives in a separate private repository. This repo holds only what the public site needs.

## Editing

Run `npx serve` here and visit http://localhost:3000. Links use clean addresses (`/about`, not `/about.html`), which GitHub Pages and `serve` both resolve to the `.html` file; `python3 -m http.server` doesn't, so links between pages 404 there. The `.html` addresses keep working too. Every push to `main` publishes.

## The Cloudflare Worker

The domain's DNS is on Cloudflare, which sits in front of GitHub Pages (#22). `cloudflare/worker.js` runs on every request and changes only what AI agents asking for Markdown (`Accept: text/markdown`) get: the homepage as `llms.txt`, and unknown addresses as a short Markdown "not found" page with a link to `llms.txt`. Both carry `Vary: Accept`. Browsers get the same pages as before, and share links (`/l/...`) are answered as below. It's deployed by hand: `cd cloudflare && npx wrangler deploy` (needs `npx wrangler login` on the Cloudflare account). A push to `main` doesn't deploy it.

It also builds the guide pages and the restaurant pages (`cloudflare/guides.js`, D92 and D103, yummers#441, #80, #81): `/guides`, `/guides/{slug}` and `/places/{slug}`, the yummers team's public lists and the places in them, read from beta with the anon key and cached for an hour. A guide is `shared_list()` (title, notes, Google place pictures) plus one embedded read of `lists` for each place's restaurant id, address, coordinates and hours. Only lists whose owner is the `yummers` account are published, and a private, empty or unknown list answers 404 (beta unreachable answers 503). **Adding a guide is one line in `GUIDES` (slug -> share id) and a deploy.** Its places get pages automatically: the address is the place's name plus area (`1978-street-food-sensok`), never its position in a list. A place page's title names what it answers ("Malis Restaurant, Tonle Bassac: What to order, hours and prices"), only the parts it has. Its What to order box is the guide note's "Try …" / "Go for …" / "Get the …" sentences (`splitNote()`) plus dishes from public ratings' Ordered text, each shown only when the team or two different people named it (`dishes()`), so one person's free text never reaches the open web alone. Near here links the three closest places from every guide within 3 km (`nearby()`), leaving out the ones in More in this guide. A place page shows the yummers account's own public review as the write-up (a `user_restaurants` row, readable by anon through RLS; left out when there is none) and a count of public Liked ratings, never a person's name, review or photo, nor Want to try. `sitemap.xml` gets every live guide and place appended by the Worker. `node cloudflare/guides.test.mjs` runs it with beta faked. The pages are a magazine layout (#80, #81): cover photo, numbered places, a place page with chips, facts and more from the guide. Display names, kinds, price and when-to-go come from `cloudflare/guide-places.js`, generated by `node cloudflare/build-guide-places.mjs <final-guides.json>... --answers <dir of fill-in answers>` (hand-kept until the answers live in the database: rerun it and commit after the team edits the fill-in page); a place missing there shows its database name and cuisine. Titles and meta descriptions use the same area as the page body, and a cuisine tag of International, Asian, Western, Fusion or Restaurant is never shown as a kind (the next tag is, else none). The same file picks each guide's cover place. Addresses never change, because they come from the database name. The area under a name is the place's `neighbourhood` (BKK1, Toul Tom Poung 1), else its `district`; Google's addresses and hours are tidied for display (`cleanAddress`, `shortHours`: "Road352 BKK1, Phnom Penh 12302, Cambodia" becomes "Street 352, BKK1, Phnom Penh", "11:00 AM – 10:00 PM" becomes "11am – 10pm"). Today's row in the hours table is chosen when the page is built, so it can lag by up to the one-hour cache. The footer on every page links to Guides.

**Restaurant pages** (`/p/{share_id}/{slug}`, D126, yummers#784, in `cloudflare/guides.js` beside the guide pages): any place in the database, read with the anon key through migration 0086's `shared_place(p_share_id)` and cached like the guides (an hour at the edge per deployed version, five minutes in browsers). The magazine layout with the picture (Google cover, else a person's public photo, credited), the open-now chip, the rating box ("N% liked it" from 5 public ratings, else "Not rated on yummers yet", D109), a Directions button, the address and hours, and the guides it is in. A wrong or missing slug is a 301 to the right one. A place that has a `/places/` page (it is in a published guide) uses that as its canonical address and its clean name and kind; every other `/p/` page is its own canonical. The chat card is `summary_large_image` with the picture, else `assets/share.jpg`. An unknown id, or beta before 0086 (no `shared_place`), is the site's 404; beta unreachable is a 503. The open-now chip uses Phnom Penh time for every place. **`/sitemap-places.xml`** lists the `/p/` address of every place with at least one public, unhidden rating that is not in a guide (a guide place's canonical is its `/places/` page, which `sitemap.xml` lists). It reads `user_restaurants` with the place's `share_id` and name embedded, 1,000 rows a read, and is cached an hour; an empty list before 0086. Unrated places still have pages but are not offered to Google: on 10 Nov Search Console had parked 5,045 of them as "discovered, not indexed" and `robots.txt` names it next to `sitemap.xml`, which stays a plain list so `build-blog.mjs` still owns it. `node cloudflare/place.test.mjs` covers it. Deploy the Worker only after 0086 is on beta.

It also answers `POST /api/signup`, the homepage's Android waitlist form (#32, `list=android`; any other kind is a 400): it checks the Cloudflare Turnstile token (and that it was issued on yummersapp.com), then emails a short note from Sovithyea (`sovithyea@mail.yummersapp.com`, replies to hello@) with a link to confirm the address, in the language the page was showing (English, Khmer or French). Nothing joins the list until that link is used (#46). The link (`/api/confirm?token=…`) opens a page that asks first, because mail scanners open links; its button saves the email as a Resend contact in one segment (`ANDROID_SEGMENT_ID`), and a new contact gets a short welcome note; joining again sends nothing. Pending sign-ups wait in the `SIGNUPS` Workers KV namespace for 7 days, and one address gets at most one confirm email a day however often the form is sent. `node cloudflare/signup.test.mjs` runs the whole flow with Turnstile, Resend and KV faked. The welcome note's unsubscribe link (`/api/unsubscribe?id=<Resend contact id>`) opens a page that asks first, because mail scanners open links; the button deletes the contact from Resend. Both notes end with Sovithyea's handwritten signature and a cream strip with the banner and social icons (#53; the images are `assets/email-signature.png`, `assets/email-banner.png` and `assets/email-<instagram|tiktok|facebook|linkedin>.png`, the footer's icons as PNGs because Gmail drops SVG, so don't rename them), and have no List-Unsubscribe header, so Gmail treats them as personal mail. It needs these secrets: `RESEND_API_KEY`, `TURNSTILE_SECRET` and `ANDROID_SEGMENT_ID` (`SEGMENT_ID` and `MELBOURNE_SEGMENT_ID` only for links emailed before 14 Nov) (set each with `npx wrangler secret put <NAME>`), and the Turnstile site key goes in `index.html`'s `data-sitekey`. Deploy the Worker before the form goes live, or sign-ups fail.

**Melbourne** (#144, yummers#786) opened on iPhone on 14 Nov 2026, so its waitlist form is gone: `/melbourne` (`melbourne.html`) is a meta-refresh to `/beta`, like `/support`. The Worker still honours what was emailed before: `/api/confirm` tokens saved as `{email, list: "melbourne", suburb, ref}` (joins `MELBOURNE_SEGMENT_ID` with the `suburb`, `invite_code` and `invited_by` contact properties) or as a plain email (the old beta list, `SEGMENT_ID`), and `/api/join-melbourne?id=` (`autosubmit.js`, `invite.js`). Delete those, the `MELBOURNE` strings and the two secrets once the 7-day tokens have expired and nobody uses the one-tap links. `node cloudflare/signup.test.mjs` covers all of it.

Share links (`/l/{id}/{slug}`, #95) get `404.html` with a compact card (`twitter:card` summary, a small square picture beside the text, like a Spotify link): the list's title, "List by @user · N places" and the cover, else the first place's picture, else `assets/share-square.jpg`. The homepage and other pages use `assets/share.jpg` (1200 × 630). A private, hidden, missing or unreadable list gets the generic card and the same 200, so nothing shows whether a list exists; answers are cached 5 minutes (not at all when the lookup fails). `404.html` + `share.js` still draw the page (#94): the app's list layout when `shared_list()` carries migration 0084's fields, today's text list when it doesn't. `node cloudflare/list.test.mjs` covers the route.

`/favicon.ico` is a 301 to `/assets/favicon-192.png`, because browsers ask for it whatever the pages say. A picture counts only when its host is one the CSP lets through (`*.googleusercontent.com` or the beta project's storage, `usable()` in `guides.js`): beta also holds Google Street View links (`streetviewpixels-pa.googleapis.com`) that never load, and those are treated as no picture (the letter tile or `assets/share.jpg`).

Every answer also carries security headers (#48): a Content-Security-Policy that allows only the site's own files, Cloudflare Turnstile, Cloudflare Web Analytics' script, PostHog's script and EU endpoint (`eu-assets.i.posthog.com`, `eu.i.posthog.com`) and the Supabase project the share page reads (change it there when share links move to beta, #224), images from that Supabase project's public photo bucket and Google's place pictures (`*.googleusercontent.com`), plus HSTS, `nosniff`, a referrer policy and no framing. Scripts must be files, not inline: the share page's script is `share.js` for that reason. Load every page with the browser console open after changing what a page loads. Cloudflare's Turnstile frame (`challenges.cloudflare.com`) logs errors of its own once it loads: `Connecting to 'data:,' violates … Content Security Policy`, `Fetch API cannot load data:,`, and some blanked `%c` lines. They come from Cloudflare's page under Cloudflare's own policy (the one quoted in the message lists its hosts, not ours), so this site's CSP can't change them and loosening it wouldn't help (#132). What the site controls is when they appear: the homepage loads `api.js?render=explicit` from `site.js` and renders the widget only when the visitor first focuses the form, so a homepage that is only read logs nothing. Every other page, and a list link, logs nothing.

The Organization data has no postal `address` until the company is registered.
