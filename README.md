# yummersapp.com

The public website for **Yummers**, a restaurant discovery app for Cambodia that is still in the making.

The app was called HungryRaccoon until October 2026 (D85). The old domain, hungryraccoonapp.com, forwards here with a Cloudflare redirect rule that keeps the path and query, so share links already sent (`/l/...`) still open (#35). The repo is `yummers-hq/yummersapp.com` (renamed from `hungryraccoon-hq/hungryraccoonapp.com`; GitHub forwards the old address).

This is a plain static page: HTML, CSS, fonts and images, with no build step. It is served by GitHub Pages on `yummersapp.com`. The only server code is the Cloudflare Worker below, which also takes the homepage's beta sign-ups (#32). It has no download links. Visits are counted by PostHog (`analytics.js`, #2): cookieless until a visitor presses Accept on the cookie banner, and Cloudflare Web Analytics (the zone's automatic setup, no cookies) still runs until the owner switches it off (#51).

The app itself lives in a separate private repository. This repo holds only what the public site needs.

## Editing

Run `npx serve` here and visit http://localhost:3000. Links use clean addresses (`/about`, not `/about.html`), which GitHub Pages and `serve` both resolve to the `.html` file; `python3 -m http.server` doesn't, so links between pages 404 there. The `.html` addresses keep working too. Every push to `main` publishes.

## The Cloudflare Worker

The domain's DNS is on Cloudflare, which sits in front of GitHub Pages (#22). `cloudflare/worker.js` runs on every request and changes only what AI agents asking for Markdown (`Accept: text/markdown`) get: the homepage as `llms.txt`, and unknown addresses as a short Markdown "not found" page with a link to `llms.txt`. Both carry `Vary: Accept`. Browsers get the same pages as before, and share links (`/l/...`) are answered as below. It's deployed by hand: `cd cloudflare && npx wrangler deploy` (needs `npx wrangler login` on the Cloudflare account). A push to `main` doesn't deploy it.

It also builds the guide pages and the restaurant pages (`cloudflare/guides.js`, D92 and D103, yummers#441, #80, #81): `/guides`, `/guides/{slug}` and `/places/{slug}`, the yummers team's public lists and the places in them, read from beta with the anon key and cached for an hour. A guide is `shared_list()` (title, notes, Google place pictures) plus one embedded read of `lists` for each place's restaurant id, address, coordinates and hours. Only lists whose owner is the `yummers` account are published, and a private, empty or unknown list answers 404 (beta unreachable answers 503). **Adding a guide is one line in `GUIDES` (slug -> share id) and a deploy.** Its places get pages automatically: the address is the place's name plus area (`1978-street-food-sensok`), never its position in a list. A place page shows the yummers account's own public review as the write-up (a `user_restaurants` row, readable by anon through RLS; left out when there is none) and a count of public Liked ratings, never a person's name, review or photo, nor Want to try. `sitemap.xml` gets every live guide and place appended by the Worker. `node cloudflare/guides.test.mjs` runs it with beta faked. The pages are a magazine layout (#80, #81): cover photo, numbered places, a place page with chips, facts and more from the guide. Display names, kinds, price and when-to-go come from `cloudflare/guide-places.js`, generated by `node cloudflare/build-guide-places.mjs <final-guides.json>... --answers <dir of fill-in answers>` (hand-kept until the answers live in the database: rerun it and commit after the team edits the fill-in page); a place missing there shows its database name and cuisine. The same file picks each guide's cover place. Addresses never change, because they come from the database name. The area under a name is the place's `neighbourhood` (BKK1, Toul Tom Poung 1), else its `district`; Google's addresses and hours are tidied for display (`cleanAddress`, `shortHours`: "Road352 BKK1, Phnom Penh 12302, Cambodia" becomes "Street 352, BKK1, Phnom Penh", "11:00 AM – 10:00 PM" becomes "11am – 10pm"). Today's row in the hours table is chosen when the page is built, so it can lag by up to the one-hour cache. The footer on every page except the unlisted `/melbourne` links to Guides.

It also answers `POST /api/signup`, the homepage's beta sign-up form (#32): it checks the Cloudflare Turnstile token (and that it was issued on yummersapp.com), then emails a short note from Sovithyea (`sovithyea@mail.yummersapp.com`, replies to hello@) with a link to confirm the address, in the language the page was showing (English, Khmer or French). Nothing joins the list until that link is used (#46). The link (`/api/confirm?token=…`) opens a page that asks first, because mail scanners open links; its button saves the email as a Resend contact in one segment, and a new contact gets a short welcome note; joining again sends nothing. Pending sign-ups wait in the `SIGNUPS` Workers KV namespace for 7 days, and one address gets at most one confirm email a day however often the form is sent. `node cloudflare/signup.test.mjs` runs the whole flow with Turnstile, Resend and KV faked. The welcome note's unsubscribe link (`/api/unsubscribe?id=<Resend contact id>`) opens a page that asks first, because mail scanners open links; the button deletes the contact from Resend. Both notes end with Sovithyea's handwritten signature and a cream strip with the banner and social icons (#53; the images are `assets/email-signature.png`, `assets/email-banner.png` and `assets/email-<instagram|tiktok|facebook|linkedin>.png`, the footer's icons as PNGs because Gmail drops SVG, so don't rename them), and have no List-Unsubscribe header, so Gmail treats them as personal mail. It needs three secrets, `RESEND_API_KEY`, `TURNSTILE_SECRET` and `SEGMENT_ID` (set each with `npx wrangler secret put <NAME>`), and the Turnstile site key goes in `index.html`'s `data-sitekey`. Deploy the Worker before the form goes live, or sign-ups fail.

**The Melbourne waitlist** (#144, yummers#786) is `melbourne.html`, served at `/melbourne`: unlisted (`noindex`, not in `sitemap.xml` or `llms.txt`, linked from nowhere), English only. Its form posts to the same `/api/signup` with `list=melbourne`, a `suburb` from `MELBOURNE.suburbs` in `worker.js`, an `adult` tick and `ref` (from `?ref=` in the page address, 8 lowercase letters or digits, else dropped). Pending sign-ups are now stored in KV as JSON (`{email, list, suburb, ref}`); older plain-email tokens still confirm into the beta segment. Confirming adds the contact to the segment in the `MELBOURNE_SEGMENT_ID` secret with the Resend contact properties `suburb`, `invite_code` (random, never the contact id) and `invited_by` (only when there is one); an existing contact keeps the invite code it has. The confirmed page and a new contact's welcome note show `https://yummersapp.com/melbourne?ref=<code>`, and `invite.js` runs the page's share button. Unsubscribing deletes the whole contact, beta list included. **Before deploying:** in Resend create the Melbourne segment and the three properties (all `string`; a property must exist before it can be set, or the call fails: [Resend contact properties](https://resend.com/docs/dashboard/audiences/properties)), then `npx wrangler secret put MELBOURNE_SEGMENT_ID`, then `cd cloudflare && npx wrangler deploy`. Merging publishes the page, so deploy the Worker first or the form fails. `node cloudflare/signup.test.mjs` covers it.

Share links (`/l/{id}/{slug}`, #95) get `404.html` with a compact card (`twitter:card` summary, a small square picture beside the text, like a Spotify link): the list's title, "List by @user · N places" and the cover, else the first place's picture, else `assets/share-square.jpg`. The homepage and other pages use `assets/share.jpg` (1200 × 630). A private, hidden, missing or unreadable list gets the generic card and the same 200, so nothing shows whether a list exists; answers are cached 5 minutes (not at all when the lookup fails). `404.html` + `share.js` still draw the page (#94): the app's list layout when `shared_list()` carries migration 0084's fields, today's text list when it doesn't. `node cloudflare/list.test.mjs` covers the route.

Every answer also carries security headers (#48): a Content-Security-Policy that allows only the site's own files, Cloudflare Turnstile, Cloudflare Web Analytics' script, PostHog's script and EU endpoint (`eu-assets.i.posthog.com`, `eu.i.posthog.com`) and the Supabase project the share page reads (change it there when share links move to beta, #224), images from that Supabase project's public photo bucket and Google's place pictures (`*.googleusercontent.com`), plus HSTS, `nosniff`, a referrer policy and no framing. Scripts must be files, not inline: the share page's script is `share.js` for that reason. Load every page with the browser console open after changing what a page loads. The homepage console still shows errors from inside Cloudflare's Turnstile frame (`challenges.cloudflare.com`): `Connecting to 'data:,' violates … Content Security Policy`, `Fetch API cannot load data:,`, a font `OTS parsing error`, and some blanked `%c` lines. They come from Cloudflare's own page under Cloudflare's own policy (the one quoted in the message lists its hosts, not ours), so this site's CSP can't change them and loosening it wouldn't help (#132). Every other page, and a list link, logs nothing.

The Organization data has no postal `address` until the company is registered.
